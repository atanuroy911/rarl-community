RARL Community Platform

Project documentation — architecture, deployment, and admin operations

What this is

A plain PHP + MySQL community platform for the Robotics & Automation Research Lab (RARL) — member registration (individuals and labs), a Discord-linked community feed, a learning resource hub, newsletters, event management, and verifiable PDF certificates with QR-code validation. No build step: Tailwind is loaded from a CDN at runtime, so the deployed app is just PHP files served directly.

Stack

PHP 8.1+, MySQL/MariaDB, Apache (mod_rewrite/mod_headers), no framework, no Composer.

Hosting

cPanel shared hosting (Namecheap), deployed as a subdomain (community.rarl-lab.com).

Libraries

Bundled, no package manager: fpdf (certificate/ID card PDFs), phpqrcode (QR codes), Parsedown.

Configuration & secrets

config.php holds no secrets and is safe to commit — every real value comes from environment variables via env() (env.php), which checks real server env vars first and falls back to a local .env file if present. .env is gitignored and excluded from every deploy, so it's set up once on the server and never touched again by CI.

Deployment: GitHub → cPanel

Every push to main runs .github/workflows/deploy.yml, which deploys to cPanel over FTPS. The app has 600+ files (mostly the bundled PDF/QR libraries), and uploading each one individually was tripping connection resets (Server sent FIN packet unexpectedly) on the shared-hosting FTP server. Instead, the workflow ships the whole app as a single zip and lets a PHP endpoint unzip it in place.

1
Checkout & zipRepo is zipped into deploy.zip, excluding .git, .github, .env*, the disposable phpqrcode mask cache, and every uploads/ subfolder holding user-generated content (avatars, certificates, CVs, ID cards, popups, templates) so a deploy never clobbers real data.
2
Upload two filesdeploy.zip and a fresh copy of deploy-extract.php are FTPS-uploaded from a staging folder — two files over the wire instead of 600+.
3
Trigger extractionA curl call hits deploy-extract.php?token=... on the live site. The token must match DEPLOY_TOKEN in the server's .env (hash_equals comparison) or it 403s.
4
Unzip & clean updeploy-extract.php unzips deploy.zip into place with ZipArchive, then deletes the zip. .env was never in the zip, so it's untouched across every deploy.

First-run database setup

Modeled on WordPress's wp-admin/install.php. When any admin page loads and dbTablesExist() finds no members table, the request is redirected to admin/install.php instead of hitting a fatal error.

  • The setup screen shows a single "Set Up Database" button that runs sql/schema.sql then sql/002_v2_features.sql (idempotent — safe to re-run, uses CREATE TABLE IF NOT EXISTS / ON DUPLICATE KEY UPDATE).
  • On success, the session is destroyed and the admin is redirected to login with a flash message — no auto-login, matching how WordPress makes you log in fresh after install.
  • If tables already exist, install.php refuses to run and redirects straight to login — it can't be used to re-trigger setup on a live site.
  • A logged-in admin can also re-run the same migrations any time from Admin → Migrations (admin/migrate.php) — useful after a deploy that adds new tables/columns (e.g. the v2 feature set).

Admin login security

  • Brute-force lockout — 5 failed logins from the same IP lock that IP out for 15 minutes. Tracked in the existing settings key/value table (no new table needed), via loginThrottleCheck/RecordFailure/Reset in functions.php.
  • Generic error messages — failed logins say "Invalid credentials," never which field was wrong.
  • Session hardening — session_regenerate_id(true) on successful login (prevents session fixation), CSRF token per admin session compared with hash_equals.
  • Security headers (.htaccess) — X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy: strict-origin-when-cross-origin, and ServerSignature Off.
  • Dotfile & sensitive-file blocking — .env*, .git*, and config.php/env.php are denied directly over HTTP; sql/ 404s.

Membership terms shown on-site

Membership is free for the first year. In exchange, members are expected to use the RARL affiliation as the second affiliation on at least one paper during that year. This is stated on the registration page and the homepage's final call-to-action — not enforced in code, just communicated up front.
